# Lobby bot and end-game controls

The host can add one bot at a time in the lobby until the room has four seats. The **Add bot** button sends an authenticated `add_bot` WebSocket command. The server checks host authority, lobby phase, capacity, and action ID before creating a tokenless bot seat; every connected human receives the updated lobby. Replaying the same action ID acknowledges the original action without adding another seat. The existing room-creation option for one to three bots and human joins remain available.

After a match starts, the host can select **End game**, then **Confirm end game**. The server applies `domain.ActionEndGame`, advances one revision, and broadcasts `game_ended` followed by `game_completed`. Scores include completed tricks only; an unfinished trick is not awarded. The final state records the ending host, keeps the public trick and each seat's own private hand in its final projection, and derives winners from current scores. Each connected seat receives that result and a terminal room-closed message before its socket closes normally. The room is removed immediately, its code can be reused, old tokens cannot reconnect, and pending bot work is canceled. The final screen stays visible until **Return to join**.

**Leave room** is available in the lobby and active match. A lobby guest leaves only their seat; remaining players see the refreshed lobby. A lobby host closes the room for everyone. During a match, any player confirms that leaving ends the match for everyone. `domain.ActionLeaveGame` uses the same early-end scoring as the host action and records the actual departing seat. The browser sends an authenticated `POST /game/leave` with room, seat, and token, clearing its saved token only after accepted leave or terminal closure. Refresh and temporary disconnect still restore a seat while its room is active.

The focused Go tests cover host-only and full-room bot addition, duplicate actions, early end during a trick and between hands, current-score winners, privacy, transient reconnect, lobby and active leave, stale tokens, immediate code reuse, normal socket closure, natural completion by a human or bot, and pending-bot cancellation. The repeatable `--browser-lifecycle-smoke` mode uses two real browsers for a scored trick, guest leave, results, code reuse, and host end. The D1 release gate and D2 deployment path remain in `scripts/test-release.sh` and `scripts/deploy-dev-pi.sh`; the deployed commit and live checks are reported with the rollout.
